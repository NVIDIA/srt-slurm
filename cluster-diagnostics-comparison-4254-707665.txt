CPU/NUMA diagnostic limitation

All four tasks were restricted to CPUs 0-3,176-179. Memory nodes 0 and 1 were
allowed, but CPU NUMA1 was unavailable. All four NUMA1 copy tests therefore
failed with sched_setaffinity: Invalid argument. Unrestricted tests also ran on
CPU NUMA0, and the pinned-buffer mappings show N0 allocation for every GPU.
Local H2D copies reach roughly 319 GiB/s; remote H2D copies reach roughly 36
GiB/s in both clusters. This demonstrates a large placement penalty, not a
Raplab-only defect. It does not establish the placement of serving workers.
The eight-CPU exact job step caused the restriction despite the job owning
352 CPUs per node. The script now requests the allocated per-node CPUs.
Equal and unequal allocation parsing was checked with mocked srun calls;
the revised NUMA1 test still needs a cluster run.
Evidence: allocation.txt, container/cgroup-limits.txt, copy-1.stderr,
container/copy-0.jsonl and copy-unrestricted.jsonl in each extracted bundle.
Slurm semantics: https://slurm.schedmd.com/srun.html#OPT_exact

Network differences to investigate

Raplab exposes eth0 as a veth, MTU 8980, and a default route through 169.254.1.1.
Its nominal eth0 speed is 10000 Mb/s; veth speed is not a reliable physical
bandwidth limit. Hecate exposes physical os_p1s0 (400000 Mb/s), storage interfaces
and eight IPoIB interfaces, with explicit subnet routes. Raplab's host-pass
network sysfs also sees the virtual interface: this isolation extends beyond
just the Pyxis container. The underlay and actual RPC latency were not measured.

The Mooncake prefix existence lookup and save existence probe are synchronous
calls in tekit. Their latency and any UCX/TCP traffic warrant comparison under
serving load. These bundles do not prove that KV payloads used TCP; RDMA is
available and raw RDMA testing previously worked. The transport environment in
settings.txt is for diagnostics, not the serving recipe. Diagnostic UCX config
also differs: Raplab UCX_NET_DEVICES=all; Hecate=os_p1s0. Worker recipes explicitly
override device settings, so do not treat this as their effective configuration.
Evidence: container/net.txt, routes.txt, ucx-config.txt, host/proc-sysfs.txt.

RDMA topology is different even though NIC specifications match. On both Raplab
nodes mlx5_0/1/2/5 report fe80:0000:0000:0000 and SM LID 1; mlx5_6/7/8/11 report
fec0:0000:0000:0001 and SM LID 35. All eight Hecate NICs report fe80 and SM LID 1.
Matching mlx5_0 and mlx5_6 names map to matching subnet prefixes across the two
sampled Raplab nodes. Subnet prefixes alone do not prove end-to-end reachability
or congestion. Verify selected source/destination NIC pairs in actual serving
logs and benchmark each intended same-subnet pair in both directions.
Evidence: container/rdma-links.txt for all four nodes.

Hardware/software similarities and differences

All selected IB NICs report 800 Gb/s XDR, PCIe 64.0 GT/s x16, and firmware
82.48.4036 on all four nodes. All active IB ports use MTU 4096. The ibv_devinfo
active_speed field says 200 Gb/s with active_width 4X; the sysfs aggregate rate
is 800 Gb/s. CPU model Olympus, 352 logical CPUs, two CPU/memory NUMA nodes,
64 KiB base pages and kernel 7.0.0-2015-nvidia-bos-64k match. NUMA balancing and
zone reclaim are disabled on all four nodes; THP policy is madvise.

All collected Python package lists match. Mooncake is 0.3.13, TRT-LLM is
1.3.0rc25, and PyTorch is 2.14.0a0+4fdf77b940.nvinternal.rubin.0.8dev.63969804.
Hashes of utils.py, Mooncake worker.py and staging.py match across all nodes.
This verifies those files, not every binary in the two images.

Raplab GPU kernel driver: 620.47; VBIOS: 99.00.16.47.12.
Hecate GPU kernel driver: 620.43; VBIOS: 99.00.16.47.0F.
Both report max SM clock 2424 MHz, max memory clock 4752 MHz, and 2300 W power
limits where applicable. Both report fabric Healthy/Full, no route recovery,
and successful fabric initialization. Observed idle clocks/P-states differ,
but these snapshots cannot establish clocks during prefill computation.
Driver/VBIOS differences remain candidates for a controlled comparison.

Both have substantial available memory and no swap. Diagnostic cgroups show
no CPU throttling or OOM events. Hecate's memory cap is lower than Raplab's.
Idle-node memory availability cannot exclude memory pressure from large donor
and worker segments during serving.

Missing evidence

Raplab NIC counters and hw_counters are absent from both scopes. There are zero
readable numeric counters in the host snapshots. Hecate has 604 numeric counter
values per node and no error/wait deltas in this idle interval. Therefore these
bundles cannot rule out Raplab transport errors, retries, or congestion.
Kernel messages were denied on all four nodes. PCI extended capabilities are
access denied, so ACS/IOMMU behavior cannot be fully compared. Container modinfo
and ofed_info failed; loaded NVIDIA driver versions are independently available.
